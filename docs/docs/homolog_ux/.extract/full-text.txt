Detalhamento dos Achados  5.1 Autenticação e Login  A01   —   [POSITIVO] E-mail e senha pré-preenchidos corretamente  Módulo / Tela   Login   —   /login  Contexto observado   O campo de e-mail exibe o endereço do usuário e o campo senha exibe os caracteres mascarados ao carregar a tela de login.  Análise técnica   Bug anterior corrigido. O preenchimento automático pelo gerenciador de senhas do navegador está funcionando conforme esperado.  Comportamento esperado  Campos de login preenchidos automaticamente pelo navegador quando há credenciais salvas.  A02   —   [MÉDIO] Seletor de organização não pré-seleciona automaticamente  Módulo / Tela   Login   —   /login  Contexto observado   O campo 'Organização' aparece com placeholder 'Selecione a organização', exigindo seleção manual antes de clicar em Entrar.  Análise técnica   Do ponto de vista de lógica de negócio, um usuário/colaborador pertence a uma única organização. Se o vínculo é 1:1, o campo deveria ser preenchido automaticamente com a organização correspondente, eliminando uma etapa desnecessária no fluxo de login.  Comportamento esperado  O campo 'Organização' deve ser pré-selecionado automaticamente quando o usuário possui vínculo com apenas uma organização. O seletor só deve aparecer quando o usuário pertence a múltiplas organizações.  Impacto   Aumenta a fricção no login diário de todos os usuários do sistema.  A03   —   [ALTO] Dropdown de organização exibe entradas duplicadas (agravado: 3 entradas ao final da sessão)  Módulo / Tela   Login   —   /login  Contexto observado   Ao abrir o seletor de organização, a mesma organização 'Rafaella Nottes Consultoria' aparece 2 vezes no início da sessão e 3 vezes ao final, após tentativas de cadastro trial.  Análise técnica   A duplicidade é consequência direta do Achado A10   —   cada tentativa de cadastro com e-mail já cadastrado gera um novo registro de organização no banco. O usuário não consegue distinguir qual das entradas é a organização legítima original, pois não há diferenciação visual (sem data de criação, sem ID, sem indicador).  Comportamento esperado  O dropdown deve exibir apenas organizações únicas e ativas vinculadas ao usuário. Registros duplicados devem ser eliminados na origem (ver A10) e o sistema deve ter constraint de unicidade por e-mail.  Impacto   O usuário pode fazer login na organização errada (duplicata) e operar em ambiente inconsistente.  A09   —   [ALTO] Ausência de mensagem de erro ao tentar entrar sem organização selecionada  Módulo / Tela   Login   —   /login  Contexto observado   Ao clicar em 'Entrar' com o campo 'Organização' vazio, o sistema bloqueia o acesso mas não exibe nenhuma mensagem de erro ou feedback visual.

Relatório de Análise de Usabilidade   —   Aero Suite v3   Rafaella Nottes Consultoria  Página 8 de 16  Análise técnica   Falha silenciosa: o sistema sabe que algo está errado (bloqueia a ação) mas não comunica ao usuário. O clique simplesmente não faz nada   —   sem destaque no campo, sem toast, sem mensagem inline. O usuário fica sem saber se o sistema travou ou se o botão está quebrado.  Comportamento esperado  Ao clicar em Entrar sem organização selecionada, exibir mensagem de erro inline abaixo do campo: 'Selecione uma organização para continuar.' com destaque visual no campo (borda vermelha + texto de erro).  Impacto   Usuários menos experientes tecnicamente podem interpretar a ausência de resposta como falha do sistema, gerando chamados de suporte desnecessários.  5.2 Cadastro Trial  A05   —   [ALTO] Pré-preenchimento indevido de e-mail e senha no formulário de nova organização  Módulo / Tela   Cadastro Trial   —   /cadastro-trial  Contexto observado   O formulário de cadastro trial exibe o e-mail e senha da sessão autenticada ativa, mesmo sendo uma tela pública destinada a novos clientes.  Análise técnica   O formulário de cadastro trial é uma tela pública destinada a novos clientes sem conta. Ao ser acessado por usuário autenticado, o sistema deveria tratar esse contexto separadamente. Além da lógica incorreta, o pré-preenchimento de senha em formulário de cadastro representa risco de exposição de credenciais em ambientes compartilhados, conforme OWASP.  Comportamento esperado  O formulário /cadastro-trial deve sempre renderizar com todos os campos vazios, independentemente de existir sessão ativa. O campo senha deve ter autocomplete='new-password' para evitar sugestões indevidas.  Impacto   Para um produto posicionado a R$10.000/mês, o fluxo de onboarding de novos clientes é crítico para a primeira impressão. Formulários pré-preenchidos com dados de outro usuário comprometem confiança e qualidade percebida.  A06   —   [MÉDIO] Checkbox de aceite legal pré-marcado  Módulo / Tela   Cadastro Trial   —   /cadastro-trial  Contexto observado   A caixa 'Aceito os Termos de uso e a Política de privacidade' já aparece marcada antes de qualquer interação do usuário, contrariando a instrução exibida na própria tela: 'Marque a caixa abaixo somente depois de ler os documentos.'  Análise técnica   O aceite de termos legais exige ação afirmativa e consciente do usuário. Pré-marcar a caixa invalida juridicamente esse aceite, pois não há evidência de consentimento genuíno. Isso contraria diretamente a LGPD (Lei 13.709/2018), que exige consentimento livre, informado e inequívoco.  Comportamento esperado  O checkbox deve iniciar desmarcado, sem exceção. O usuário deve marcar ativamente após ler os documentos.  Impacto   Risco jurídico de invalidade do aceite de termos. Não conformidade com LGPD.  A07   —   [ALTO] Sistema exibe 'Organização criada' para e-mail já cadastrado e não bloqueia submissão  Módulo / Tela   Cadastro Trial   —   /cadastro-trial  Contexto observado   Ao submeter o formulário com um e-mail já existente no sistema, a mensagem exibida foi 'Organização criada. Faça login com o e-mail e a senha do administrador.'   —   o que é factualmente incorreto.

O sistema deveria validar a unicidade do e-mail antes de qualquer gravação e bloquear a submissão com mensagem clara. A10   —   [CRÍTICO] Sistema cria registros de organização duplicados no banco a cada tentativa de cadastro com e-mail já existente  Módulo / Tela   Cadastro Trial   —   /cadastro-trial  Contexto observado   A cada nova tentativa de cadastro trial com o mesmo e-mail, um novo registro é criado no banco. O dropdown de login passou de 2 para 3 entradas 'Rafaella Nottes Consultoria' ao longo da sessão.  Análise técnica   Falha grave de integridade de dados. A tabela de organizações não possui constraint de unicidade por e-mail, ou ela não está sendo aplicada antes da inserção. Em produção, isso representa risco sério de corrupção da base ao longo do tempo. Os Achados A05, A07 e A10 formam uma cadeia: formulário pré-preenche e- mail existente → permite submissão sem validar duplicata → cria registro indevido → novo registro aparece no  dropdown.  Comportamento esperado  Validar unicidade do e-mail antes de qualquer INSERT. Adicionar constraint UNIQUE na coluna de e-mail administrador da tabela de organizações. Realizar limpeza dos registros duplicados já existentes no ambiente de homologação.  Impacto   Integridade do banco comprometida. Usuário não sabe qual organização selecionar no login. Risco de isolamento de dados entre tenants.  5.3 Assistente de Configuração da Empresa  A12   —   [MÉDIO] Campo 'Cor Primária da Marca' sem propósito claro e com valor padrão do fornecedor  Módulo / Tela   Assistente Config.   —   Etapa 1 Marca  Contexto observado   O campo exibe dois quadrados de cor azul e um código hexadecimal #0ea5e9 sem explicação do que representam os dois quadrados. O valor padrão é exatamente o azul do próprio Aero Suite.  Análise técnica   A cor NÃO é extraída automaticamente da logo   —   exige preenchimento manual pelo usuário. A função é legítima (usada em login, propostas e documentos), mas está mal comunicada. O valor padrão #0ea5e9 faz com que todos os documentos gerados saiam com a cor do fornecedor, não do cliente.  Comportamento esperado  Rotular cada quadrado de cor, oferecer color picker visual além do campo hex, orientar como obter o código da marca, e definir valor padrão neutro com aviso de personalização necessária.  Impacto   Clientes que não perceberem o campo terão documentos gerados com a identidade visual do Aero Suite, não da sua própria empresa. A15   —   [ALTO] Campo Telefone Comercial sem máscara, sem limite de caracteres e sem validação   —   aceita qualquer string  Módulo / Tela   Assistente Config.   —   Etapa 2 Contatos  Contexto observado   O campo aceitou a string 'ddddddddddddddddddddddddddd' (27+ caracteres, somente letras) sem qualquer restrição. O sistema avançou normalmente para a próxima etapa.  Análise técnica   Três problemas: (1) ausência de validação de tipo   —   campo aceita letras; (2) ausência de limite de caracteres   —   número internacional E.164 tem máximo 16 caracteres; (3) ausência de máscara ou placeholder orientativo. Este achado causou diretamente o Achado A22 (Data Truncation no banco).  Comportamento esperado  Aceitar apenas dígitos, +, (, ), - e espaços. Limitar a 20 caracteres (E.164). Adicionar placeholder orientativo ex: +55 (21) 99999-9999. Implementar validação de formato antes do envio ao servidor.  Impacto   Dados inválidos cascateiam para erro de banco (A22) e impossibilitam a conclusão do assistente.  A18   —   [ALTO] Campo CNPJ sem máscara de formatação   —   exibido como sequência numérica bruta  Módulo / Tela   Assistente Config.   —   Etapa 3 Empresa  Contexto observado   O CNPJ é exibido como '12354222000156' sem a máscara padrão XX.XXX.XXX/XXXX- XX. Além disso, o campo não está preparado para o novo formato alfanumérico de CNPJ previsto pela Receita Federal para julho de 2026.  Análise técnica   A ausência de máscara dificulta a conferência visual e aumenta risco de erro de digitação. O novo CNPJ alfanumérico (IN RFB 2.229/2024) entrou em vigor a partir de julho de 2026   —   o campo deve suportar o formato alfanumérico para não se tornar obsoleto imediatamente após o go-live. Impacto   Sistema pode rejeitar CNPJs válidos no novo formato alfanumérico após julho de 2026.
