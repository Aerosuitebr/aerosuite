01Visão Geral e Recomendação Estratégica

Tese central do plano em uma página

Recomendação principal: Adotar estratégia MRO-First (Wedge Strategy) — comercializar primeiro como suite especializada para manutenção aeronáutica, usando a operação atual da Aero Suite como case de prova, e só após validação no nicho expandir o núcleo horizontal para outros setores industriais.

O Aero Suite possui um ativo técnico relevante já operando em produção: stack moderna (Quarkus 3 + Java 21 + Angular 18), arquitetura em camadas, domínio rico para operação MRO (Ordens de Serviço, FCU, kits, estoque com rastreio FIFO, propostas comerciais, portal externo). Esse conjunto representa de 18 a 24 meses de desenvolvimento que não precisa ser refeito.

Por outro lado, no estado atual o sistema é monolítico single-tenant, com autenticação frágil, branding "Aero Suite" embutido no código e ausência de mecanismos de isolamento por empresa. Esses pontos são bloqueadores objetivos para vender ao segundo cliente — mas todos endereçáveis em 3 a 6 meses de trabalho focado.

As 4 decisões fundamentais

01

Foco em nicho antes de horizontalizar

Dominar o mercado MRO brasileiro primeiro (~150 oficinas RBAC 145), depois extrair o core comum para indústria geral.

02

Cloud Single-Tenant para começar

Uma stack Docker isolada por cliente em VPS dedicada. Reusa 100% do que existe hoje, sem dependência de multi-tenancy completo.

03

Preço-âncora MRO Pro: R$ 4.490/mês + setup

Posicionamento premium-acessível, com setup obrigatório que filtra cliente curioso e antecipa caixa.

04

P0 técnico imediato: Flyway → JWT → Tenancy

Migrações versionadas, autenticação real e isolamento por tenant antes de qualquer prospecção externa séria.

03Classificação dos Módulos

O que serve para qualquer empresa, o que é nicho de alto valor, o que precisa generalização

(A) Núcleo Genérico — serve qualquer empresa

Tudo isso compõe a "Plataforma Base", vendida em todos os planos.

Autenticação Usuários Perfis Funcionalidades (RBAC) Controle de Acesso Notificações Chat Interno Suporte (Tickets) Backup Configurações

(C) Operacional Crítico — adaptável a vários setores (o "ouro comercial")

Empresas de manufatura, MRO, distribuição e instaladoras técnicas pagam alto por estoque rastreado + propostas + portal cliente. Após remover dependências específicas de FCU/OS aeronáutica, vira o coração de produtos para múltiplos verticais.

Estoque FIFO Rastreio por Lote Invoices Fornecedores Movimentações QR Code Propostas Comerciais Templates Clientes Portal Externo Biblioteca de Documentos Relatórios

(B) Vertical Aeronáutica — nicho de ticket alto

Em vez de descartar, esse conjunto vira "Módulo MRO Aviation" — extensão paga premium, vendida para oficinas RBAC 145 / Part-145. É o diferencial vertical que justifica preços enterprise.

Multi-Tenant SaaS

Escala self-service para PMEs
  • Cliente PME entra no plano multi-tenant
  • Premium / regulado continua no dedicado
  • 2 SKUs vendidos em paralelo
  • Onboarding self-service (trial 14 dias)
  • Stripe / Pagar.me — recorrência automática
Marco: R$ 100k+ MRR com 20+ clientes
🥉 Onda 3 · Mês 18+

On-Premise opcional

Destrava enterprise de grande porte
  • Instalador empacotado para datacenter cliente
  • Setup R$ 80k+ + manutenção anual
  • Não é produto principal — destravador de venda
  • Permite vender a aviação grande, militar, regulado
Marco: 1–2 contratos enterprise/ano

09Roadmap Técnico em 3 Ondas

Ordem inegociável de prioridades — pular ondas custa caro depois

P0 · 8–12 semanas

Fundação inegociável

Sem isso, NÃO prospecte 2º cliente
  • Flyway versionando o schema
  • JWT assinado (RS256) + bcrypt nas senhas
  • @RolesAllowed em todos os endpoints sensíveis
  • Tabela tenant + coluna tenant_id nas tabelas
  • Filtro automático no Hibernate por tenant
  • CI/CD no GitHub Actions
  • Auditoria de acesso (login, falha, permissão)
  • Backup automatizado + restore testado
  • Remover endpoints /api/test-* e /api/fix do prod
Marco: 2 tenants isolados no mesmo banco, sem vazamento
P1 · 6–10 semanas

Pronto para vender

Habilita prospecção comercial
  • White-label completo (logo, cores, nome, e-mail)
  • i18n completo (pt-BR + en) com @ngx-translate
  • Portal LGPD (termos, aceite, exclusão de dados)
  • Onboarding self-service
  • Billing via Stripe / Pagar.me
  • Feature flags por tenant (módulo MRO)
  • Hardening de logs (sem PII, sem print)
  • OpenAPI publicado em /q/openapi-ui
Marco: cliente externo se cadastra e usa em domínio próprio
P2 · 3–6 meses contínuos

Competitivo de mercado

Atinge ticket enterprise
  • Prometheus + Grafana + OpenTelemetry
  • Migração para Kubernetes (Helm chart)
  • SSO corporativo (SAML / OIDC)
  • API pública com rate limiting
  • Mobile (Ionic) para estoque/QR
  • Marketplace de integrações
  • Cobertura de testes ≥ 60% + E2E Playwright
  • Certificação SOC2 Type I ou ISO 27001
Marco: 1º contrato enterprise (Banco Brasil, Embraer, etc.)

11Valor de Mercado e Saída

Quanto a empresa pode valer ao longo da jornada

Múltiplos típicos para SaaS B2B vertical regulado no mercado brasileiro 2024–2026, baseados em movimentações observadas (aquisições TOTVS, Linx, Sankhya, expansão de fundos como Astella, Kaszek e Monashees no setor):

Estágio ARR estimado Múltiplo aplicável Valuation potencial
Ano 1 (semente)R$ 336k4–6×R$ 1,3M – R$ 2M
Ano 2 (validado)R$ 1,9M5–7×R$ 9M – R$ 13M
Ano 3 (escala)R$ 4M6–8×R$ 24M – R$ 32M
Ano 5 (líder de nicho)R$ 10–15M7–10×R$ 70M – R$ 150M
Por que vertical regulado tende ao topo da faixa: defensibilidade alta (compliance + relacionamento + vocabulário técnico), churn naturalmente baixo, expansão dentro do cliente (upsell de módulos e usuários), e mercado total bem dimensionado (não é "tamanho infinito", o que assusta investidor, mas é grande o suficiente para R$ 20M+ ARR).

Cenários de saída possíveis (mês 36–60)

  1. Aquisição estratégica por TOTVS, Senior ou Linx (querem entrar no vertical MRO)
  2. Aquisição por player global (CMMS internacional querendo presença Brasil)
  3. Aquisição por fabricante aeronáutico (Embraer Services, Helibras) querendo capturar valor da cadeia MRO
  4. Investimento Série A (R$ 8–15M por 15–25% da empresa) para acelerar internacionalização
  5. Manter empresa privada, distribuindo dividendos crescentes (~R$ 1M/ano a partir do Ano 2)

12Próximos Passos Concretos

O que fazer nas próximas 4 semanas

1

Criar branch saas/foundation no Git

Toda mudança de P0 nasce isolada. A Aero Suite continua na main sem risco até a primeira onda de validação.

2

P0 #4 — Migrar para Flyway (2–3 dias)

Adicionar quarkus-flyway no pom.xml; consolidar schema atual como V1__baseline.sql; converter scripts de db/scripts/ em migrações versionadas. Base obrigatória para tudo que vem depois.

3

P0 #1 — JWT real + bcrypt (4–7 dias)

Substituir o "token Base64" atual por JWT assinado (RS256). Hash de senhas com bcrypt. Aplicar @RolesAllowed nos resources sensíveis (OSResource, EstoqueResource, UsuarioResource).

4

Documento de visão de produto (1 página)

Definir: nome comercial da suite, posicionamento, ICP (Ideal Customer Profile), 3 dores que resolve, 3 features-âncora. Esse documento orienta marca, marketing e roadmap.

5

Calculadora de ROI para apresentação comercial

Planilha que recebe parâmetros do prospect (nº OS/mês, valor médio peça, horas técnicas) e mostra economia esperada no Ano 1 com o sistema. Forte no fechamento.

6

Identificar 1 oficina-piloto fora da Aero Suite

Indicada, dentro da rede, com desconto pesado ou gratuita por 6 meses em troca de feedback estruturado e direito de usar como case. Ideal: oficina pequena/média da rede aeronáutica regional.

7

Documentos legais essenciais

Contrato SaaS, Termo de Adesão, Política de Privacidade, DPA (Data Processing Agreement). Orçamento com advogado especializado: R$ 4–8k — investimento que se paga no 1º contrato.

8

Página comercial mínima (landing page)

Domínio próprio (ex.: aerosuite-suite.com.br), 1 página com proposta de valor, case Aero Suite, formulário de contato. Sem self-service ainda — apenas captura de lead.

Pacote mínimo dos próximos 30 dias: Flyway + JWT + página comercial + documento de visão. Com isso você sai do "sistema interno" para "produto comercial em validação" sem mexer no que a Aero Suite usa hoje.
