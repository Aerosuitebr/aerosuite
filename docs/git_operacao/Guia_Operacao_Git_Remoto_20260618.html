Capítulo 02

Autenticação GitHub CLI

Antes de push, pull ou criação de PR, o gh deve estar autenticado com escopos repo e workflow (obrigatório para enviar arquivos .github/workflows/).

Primeiro login

  1. 1 Abra PowerShell e execute: gh auth login
  2. 2 Escolha: GitHub.com → HTTPS → Login with a web browser
  3. 3 Copie o código exibido e autorize em https://github.com/login/device
  4. 4 Na tela “Authorize GitHub CLI”, confirme acesso à organização aerosuite-br
  5. 5 Se o push falhar por workflow, execute: gh auth refresh -h github.com -s workflow,repo,read:org,gist
  6. 6 Valide: gh auth status (deve listar workflow entre os escopos)
  7. 7 Configure Git para usar credenciais do gh: gh auth setup-git

Verificação rápida

gh auth status
git remote -v
git branch -a

Clonar e configurar o repositório local

Desenvolvedores que ainda não possuem cópia local devem clonar a branch desenv e configurar identidade Git.

Clone inicial (HTTPS)

cd D:\Desenvolvimento
git clone https://github.com/aerosuite-br/aerosuite.git
cd aerosuite
git checkout desenv
git pull origin desenv

Remote já existente (atualizar URL)

git remote set-url origin https://github.com/aerosuite-br/aerosuite.git
git fetch origin
git branch -u origin/desenv desenv

Configuração de identidade (uma vez por máquina)

  • git config user.name "Seu Nome"
  • git config user.email "seu.email@aerosuite.com.br"
  • Use o e-mail corporativo associado à conta GitHub

Capítulo 04

Estratégia de branches e fluxo diário

O trabalho cotidiano ocorre em desenv. Releases e deploy em produção partem de master, sempre via Pull Request após CI verde.

desenv ──(PR + CI verde)──► master ──(tag v*)──► deploy produção

Papéis das branches

desenvIntegração contínua, homologação UX, correções do dia a dia
masterLinha de produção — somente merge revisado
saas/**Features SaaS isoladas (CI monitora)
tags v*Marcos de release (ex.: v1.0.0)

Rotina diária (desenv)

  1. 1 git checkout desenv
  2. 2 git pull origin desenv
  3. 3 Implementar alterações e testar localmente
  4. 4 git status — revisar arquivos (não commitar target/, node_modules/, .env)
  5. 5 git add <arquivos relevantes>
  6. 6 git commit -m "tipo(escopo): descrição clara"
  7. 7 git push origin desenv
  8. 8 Aguardar CI verde em GitHub → Actions
No plano GitHub Free com repositório privado, branch protection automática exige upgrade. Até lá: disciplina de PR + CODEOWNERS + revisão humana em master.

Capítulo 05

Pull Requests e revisão

Toda entrada em master deve passar por Pull Request. O repositório inclui template de PR e CODEOWNERS para orientar revisão.

Abrir PR desenv → master

  1. 1 Com desenv atualizado e push feito, acesse o repositório no GitHub
  2. 2 Clique em “Compare & pull request” ou: gh pr create --base master --head desenv
  3. 3 Preencha o template: resumo, checklist CI, tipo de mudança
  4. 4 Aguarde jobs: Backend (Maven), Frontend (npm), Menu i18n audit
  5. 5 Após aprovação, use “Squash and merge” ou “Merge commit” conforme política da equipe
  6. 6 Delete branch temporária se aplicável

Boas práticas de commit

  • Prefixos: fix, feat, chore, docs, test, refactor
  • Mensagem no imperativo: “corrigir validação PN” não “corrigido…”
  • Um commit = uma intenção lógica; evite commits gigantes
  • Não incluir artefatos de build (backend/target, .tmp-*)
  • UI nova: chaves i18n em pt-BR, en-US, es-ES, fr-FR

Capítulo 08

Release e deploy produção

Após merge em master, marque a release com tag semântica e siga o checklist de deploy no servidor Hetzner.

Release versionada

  1. 1 git checkout master && git pull origin master
  2. 2 git tag -a v1.0.0 -m "Release 1.0.0 — descrição"
  3. 3 git push origin v1.0.0
  4. 4 Opcional: criar GitHub Release com notas a partir da tag

Deploy servidor (/opt/aerosuite)

  1. 1 SSH no VPS Ubuntu 24.04 (Hetzner)
  2. 2 git clone ou git pull em /opt/aerosuite (branch master ou tag)
  3. 3 Configurar .env.production (ver docs/DEPLOY-PRODUCAO.md)
  4. 4 docker compose -f docker-compose.yml -f docker-compose.production.yml up -d --build
  5. 5 Executar smoke pós-deploy (scripts/deploy/pre-deploy-check.ps1)

Capítulo 09

Solução de problemas

Erros frequentes e resolução objetiva.

Push rejeitado: OAuth App cannot update workflow without workflow scope
Execute gh auth refresh -h github.com -s workflow,repo,read:org,gist e autorize no navegador.
setup-node: unable to cache dependencies
Garanta que frontend/package-lock.json está commitado. Use npm ci no frontend.
CI falha em Menu i18n audit
Adicione chaves menu.func.* faltantes em menu-i18n.ts nas 4 línguas. Rode audit-menu-i18n.ps1 -SkipApi.
Conflito ao fazer pull
git stash → git pull → git stash pop. Resolva conflitos, teste, commit e push.
Remote incorreto (404)
git remote set-url origin https://github.com/aerosuite-br/aerosuite.git
