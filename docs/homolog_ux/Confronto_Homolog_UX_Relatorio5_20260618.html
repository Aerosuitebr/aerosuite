Achados críticos (R-10, R-13)

Bloqueadores de Conformidade Técnica e checklist Go-live.

R-10 Falha sistêmica ao salvar qualquer registro no bloco Conformidade Técnica CRITICO ✓ Verificado - ok
Módulo: Conformidade Técnica (5 submódulos)
Antes (relatório consultora)
Em AD/SB, Calibração, Documentos controlados, Habilitações e Não conformidades, salvar retornava "Ocorreu um erro inesperado" — 8 tentativas, 100% de reprodução.
Depois (ação corretiva)
ConformidadeNaoConformidadeService e SgqDocumentoService: entityManager.flush() após persist antes de operações dependentes do id; FieldLengthValidator nos campos de texto; revisão padrão "00" em documentos SGQ.
Evidência de verificação
POST API: 5/5 módulos Conformidade Técnica salvaram (AD/SB, Calibração, Documentos SGQ, Habilitações, NC) — status 201, sem erro inesperado
Como reproduzir
POST API nos 5 módulos — status 201, sem erro inesperado (reteste pós-deploy).
R-13 Checklist 100% concluído sem tarefas reais + falha ao salvar progresso CRITICO ✓ Verificado - ok
Módulo: Kit Go-live (30 dias)
Antes (relatório consultora)
15/15 itens marcados sem atividade real; "Salvar progresso" retornava "Falha ao salvar checklist".
Depois (ação corretiva)
GoLiveMigracaoService.sanitizarProgressoInflado() reseta progresso inflado em tenants sem atividade; flush() no save; translateApiError no frontend.
Evidência de verificação
API tenant default: checklist 0/15 concluídos; PUT save status=200. UI go-live: salvar progresso OK, sem 100% inflado para tenant ativo
Como reproduzir
API tenant default: 0/15 concluídos; PUT save 200; UI salvar progresso OK.
